# 2026-10-11 批量操作期间停止/急停热键失效与 Ctrl+C 崩溃修复

## 问题

F1 整理背包时程序经常以 `KeyboardInterrupt`（tkinter mainloop 内）崩溃退出。

根因链：

1. 背包整理/石碑/地图批量操作会长时间合成按住 Ctrl/Shift（`run_dump` / `apply_currency_to_bag`）。
2. `keyboard.add_hotkey` 按「当前按下键集合精确匹配」触发：修饰键被按住期间，再按 F1（停止）与 F12（急停）都不匹配，**停止热键与全局急停全部失效**。
3. 用户无法停止，只能到终端按 Ctrl+C → 主线程 mainloop 抛 `KeyboardInterrupt` → 进程直接被杀，工作线程的 `finally` 不执行，合成按住的 Ctrl 可能残留在系统中。

## 修复

- `poe2_tools/core/hotkey.py`：单键热键（f1/f2/f6/f7/f12 等）改用 `keyboard.on_press_key` 注册，触发不受按住修饰键影响；组合键（ctrl+f7）仍用 `add_hotkey`。注销统一改为直接调用注册时返回的 remover。
- `poe2_tools/ui/app.py` `run_app()`：
  - 安装 SIGINT 处理器：有按键被批量操作按住（`core_input.held_keys()` 非空）时忽略 Ctrl+C 并提示改用功能热键/F12，避免进程被杀导致按键卡死；空闲时 Ctrl+C 仍正常退出。
  - `mainloop` 捕获 `KeyboardInterrupt` 后走 `app.on_close()` 优雅清理（急停释放按键 + 注销热键 + 保存配置），不再打印堆栈。

## 验证

- `uv run pytest`：286 passed
- 游戏内人工验证待做：F1 整理中再按 F1 可停止、整理中按 F12 可急停、整理中终端 Ctrl+C 被忽略、空闲时 Ctrl+C 可正常退出
