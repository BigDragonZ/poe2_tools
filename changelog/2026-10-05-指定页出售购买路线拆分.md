# 交易 · 指定页：物品 出售/购买 路线对比

日期：2026-10-05

## 背景

「交易 · 指定」页原本只有通用的 A⇄B 买卖四列比例表，看不出「我要出货/收货该走哪种通货、挂单还是即时」。参考左旋提升之兆出货分析（挂神圣单 1:8 最优，折 0.125 神圣/个；吃崇高买单 1:22 最差），把指定页的物品数据拆分为 出售 / 购买 两部分并折神圣对比。

## 变更

- `web/trading.py`：新增纯逻辑 `item_trade_routes(custom_rates, default_rates)`——按物品分组，
  出售（挂单出售=参考通货→物品卖单价等成交；即时成交=吃物品→通货买单）与
  购买（即时购买=吃通货→物品卖单；挂单收购=参考物品→通货买单价等成交），
  每条路线给出每 1 物品的通货数量与折神圣（经 default 类别三通货最优兑换路径折算）；
  出售按折神圣降序、购买按升序，首条即最优路线。
- `web/app.py`：`/api/trade/state` 在 category=custom 时新增 `custom_view` 字段。
- `web/static/index.html`：新增 `CustomRoutesPanel`（出售/购买两张路线表 + 每物品「出售最优」结论行，
  最优路线高亮并标注「最优」），仅在「指定」页展示，位于套利方案面板之上。
- `tests/test_trading.py`：新增 5 个用例（出售最优=挂神圣单、购买最优=挂崇高买单、
  排序方向、缺默认比例时折神圣为 None 且沉底、无物品时返回空）。

## 验证

- `uv run pytest`：265 项全部通过。
- 浏览器自动化（playwright）：「交易 · 指定」页正常渲染，出售/购买两表、四种方式文案、
  折神圣列与最优标注齐全，控制台无报错；截图 `temp/browser/07_trade_custom_routes.png`。
- 实测数据（左旋提升之兆，2026-10-05 抓取）：出售最优 = 挂神圣单 1:8（0.125 神圣/个），
  购买最优 = 挂崇高买单 1:22（折 0.0314 神圣/个），与手工分析一致。
