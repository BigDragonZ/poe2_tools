# 功能说明

> 功能文档：解释各模块功能及使用方式，含待完成清单（人工验证后更新状态）。

## Python 桌面端（tkinter，`poe2_tools/`）

桌面端已于 2026-10-01 从 AutoHotkey v2 全量迁回 Python 分层架构（`poe2_tools/`：config / core / modules / bridge / ui），功能与 AHK 版等价。执行 `uv run python main.py` 启动；配置存于根目录 `poe2_tools.ini`（UTF-8）。首次启动时若存在旧版 AHK 配置（`ahk/poe2_key_helper.ini`）会自动迁移。旧 AHK 版保留在 `ahk/` 目录作回退对照，人工验证通过后删除。

界面分为（2026-10-03 重构）：顶部全局状态栏（POE2 前台 / 战斗 / 整理 / 石碑 / 地图 / 当前配置 / 当前模块 / 急停 F12）、模块导航栏（战斗 / 通用 / 研发 / 交易，位于状态栏正下方）、中部 StackedView 四大模块（战斗 / 通用 / 研发 / 交易）、底部可折叠全局日志面板（按级别着色，显示阈值由研发模块的日志级别与调试模式驱动）。各模块内嵌子标签并携带自己的配置区：**战斗**（配置1 / 旋风 + 战斗宏热键）、**通用**（整理 / 石碑速点 / 地图速点合并单页：顶部汇总三功能热键，背包网格配置通用，各功能参数分区平铺；热键行为「当前值展示 + 设置热键捕获 + 手动输入」，保存后生效）、**研发**（开发 / 测试 / 坐标 + 调试模式、日志级别）、**交易**（占位页）。**功能热键与模块页无关**：战斗/整理/石碑/地图/F3/F4 在 POE2 前台即生效，战斗宏作用于当前激活的配置页（切「配置1/旋风」子标签即切换激活配置）；页面级动作键归属各自子页——F5 标定（旋风 Q6 / 坐标货币 / 开发测量）、F2 记录（测试子页），功能热键与当前子页动作键同键时动作键优先；页不对时按动作键会在日志提示归属页，`F12` 急停始终全局生效。

### 战斗宏

1. 界面含 1 个配置页，8 个按键行：左键、右键、空格、Q/W/E/R/T
2. 每个按键可配：策略（禁用 / 连点 / 按住不放）、执行间隔（毫秒，下限 50）、随机抖动（毫秒，实际间隔 = 执行间隔 + 0~抖动值）
3. 战斗宏启停热键默认 `F2`，仅 POE2 窗口前台时生效，作用于当前激活的配置页；启动时连点键首次触发随机错开避免同帧
4. 连点由 10ms 调度器按到期时间驱动（pydirectinput / DirectInput 扫描码发送），间隔精确不漂移；POE2 窗口失焦自动停止并释放所有按住键；`F12` 全局紧急停止并释放 Ctrl/Shift/Alt/鼠标键

### 背包一键存仓

1. 游戏窗口内：鼠标指向背包第 1 格中心按 `F3`，指向右侧相邻格中心按 `F4`，格子间距自动保存
2. 行数 / 列数 / 整理间隔在「通用」模块调整（背包网格为整理/石碑/地图通用，默认 5 × 11，间隔默认 30ms、±30% 随机抖动，范围 5-5000ms；整理为快速操作：鼠标瞬间移动 + 直接点击）
3. 鼠标放到第 1 格中心，按整理热键（默认 `F1`）开始：按住 Ctrl 按行优先遍历点击；整理中再按一次热键停止
4. 整理中窗口失焦或按 `F12` 自动中断并释放 Ctrl

### 旋风配置

「旋风」子标签（「战斗」模块内）是战斗宏的特殊配置页，用同一个战斗热键（默认 `F2`）启停：

- 鼠标左 / 中 / 右键：与普通配置页相同，可配策略（禁用 / 连点 / 按住不放）、间隔、随机抖动

### 坐标页（货币坐标管理）

「坐标」子标签（「研发」模块内）集中管理所有脚本用到的货币坐标，从 ini（`[Currency]` 节）读取并展示（双列布局：左列三级货币、右列普通货币）：

- 三级货币：蜕变 / 增幅 / 富豪 / 崇高 / 混沌，只需标定**一级**坐标；二级 = 一级 +70px、三级 = +140px（向右推导）
- 普通货币：点金石 / 瓦尔 / 磨刀石 / 护甲片 / 奥术师
- 标定方法：点该行「标定」→ 切到游戏窗口，鼠标指向该货币按 `F5` 记录（再点一次「标定」取消）；坐标立即写入 ini 并刷新显示

### 石碑速点

按住 Shift → 移动到所选货币坐标右键选中 → 移动到背包逐格左键 → **完成后自动触发一次背包整理**，批量把货币应用到石碑/装备上：

1. 「坐标」页标定所用货币坐标，F3/F4 标定背包格距
2. 「通用」模块「石碑速点」区选择石碑货币与级别（级别仅对三级货币生效）、石碑间隔（默认 50ms，±30% 抖动，范围 5-5000ms）
3. 游戏内鼠标放到背包第 1 格中心，按石碑速点热键（默认 `F6`）开始；再按一次停止
4. 失焦或按 `F12` 自动中断并释放 Shift（中断时不触发整理）

### 地图速点

按顺序执行：点金石×每格 1 次 → 崇高×每格 4 次 → 瓦尔×每格 1 次 → **完成后自动触发一次背包整理**，批量给地图上点金/崇高/瓦尔：

1. 「坐标」页需已标定：点金石、崇高（一级）、瓦尔；F3/F4 标定背包格距
2. 地图间隔在「通用」模块「地图速点」区配置（默认 50ms，±30% 抖动，范围 5-5000ms）
3. 游戏内鼠标放到背包第 1 格中心，按地图速点热键（默认 `F7`）开始；再按一次停止
4. 每个阶段都是"Shift 按住 → 货币坐标右键选中 → 移动至背包逐格左键 N 次"；失焦或 `F12` 中断（中断时不触发整理）
5. 瓦尔阶段间隔不低于 500ms 兜底（腐化有动画，避免漏点）

修改配置后点所在模块配置区的"保存配置"生效（热键即时重注册）；关闭窗口自动保存并退出。

### 刷图自动化（控制并入「旋风」页）

极简健康刷图：接管高频长按与重复点击，玩家只控制鼠标指向。三线程生产者-消费者模型（dxcam 截图 → 视觉仲裁 → SendInput 输入执行），确定性 FSM（IDLE / MOVING / LOOTING / COMBOS）严格优先级仲裁：

1. 「旋风」页「刷图自动化」分区点「启动」后切回 POE2 窗口，检测到前台自动启动（15 秒内有效，超时需重新点「启动」）；游戏内按鼠标侧键 XButton2 切换 移动/关闭：移动模式脚本负责按住左键，玩家控制指向。注意：战斗热键 F2 只管战斗宏（旋风三键连点/按住），不会启动刷图助手
2. 拾取：光标附近检测到物品黑框（HSV 黑色掩模 + 长宽比/面积筛选 + Canny 文本密度校验）自动执行「挂起移动 → 光标锁定 30ms → 左键单击 → 200~600ms 消失监听」；超时黑框仍在则该坐标进黑名单（网格量化，5s 有效）后恢复移动
3. 连招：Q 层数满 6 自动执行「MouseUp → E → 60ms → Q」，强制 500ms 冷却去抖；同帧拾取与连招同时满足时拾取优先，拾取结束后接招
4. Q=6 检测用 **F5 + 右键两角标记标定**：「旋风」页刷图分区点「标定 Q=6」→ 游戏内确认 Q 图标正显示 6 后按 `F5` 进入标记 → 右键点击检测数字的**左上角**，再右键点击**右下角** → 两点矩形写入 ini `[Mapping] q6_roi`，同时截取该区域存 `templates/q6.png` 作检测模板；标记中再按 `F5` 重新开始，点界面按钮取消；重新标定后掩模热重载立即生效；未标定时 COMBOS 检测自动禁用并提示（不崩溃）
5. UI 感知：打开背包/地图等（I / Tab / Esc）自动挂起，再按恢复；每 500ms 校验前台，失焦强制压入 IDLE；侧键关闭/停止/F12 都会补发物理 Left Up 清空模拟输入
6. 参数配置在 `poe2_tools/modules/mapping/config.json`（system/loot/combos 三段，缺失字段自动回落默认值）
7. 所有注入带拟人化抖动（注入前 5~15ms、按键按下时长 15~35ms、组合键间隙 ±5ms 正态）
8. 排查指引：执行日志在 `logs/mapping.log`（毫秒时间戳，含启动配置摘要、启动时 Q ROI 截图测试、FSM 转移与原因、动作链、Q 匹配度每 2 秒节流输出）；每次启动会对标记区域截图做匹配测试：实况图存 `templates/q6_live.png`，亮像素/匹配度/阈值判定写入日志，未达标时界面日志提示，可与模板 `templates/q6.png` 肉眼对比；标定后掩模热重载立即生效，禁用状态下每 2 秒自动重试加载

### 测试页（输入记录分析）

「测试」子标签（「研发」模块内）用于采集玩家手动刷图时的操作习惯，提取技能释放频率数据：

1. 切到游戏按 `F2` 开始记录，正常刷图；再按一次 `F2` 停止并保存一轮（`logs/recordings/round-*.json`）；只记录「按下」事件：鼠标全部键位（含点击位置）+ Q/E
2. 连续记录几轮后点「分析记录」，输出各键位的总次数、次/分、中位/平均间隔；「清空记录」删除全部轮次文件（有确认）
3. 分析自动过滤无效操作：同键间隔 <80ms 视为长按自动重复/抖动丢弃；相邻事件间隔 >10s 切开活跃片段（回城/喝水等停顿不计入频率分母）；<5s 的碎片片段丢弃
4. 注意：`F2` 只在「测试」子页生效（各子页热键独立，与配置/旋疯子页的战斗热键不冲突），记录前需先切到「测试」子页；记录期间请勿启停刷图助手（其停止时会清空全部鼠标/键盘钩子）

### 开发页（测量坐标与框选范围）

「开发」子标签（「研发」模块内）负责收集开发阶段需要的信息，默认 6 个测量坐标 + 6 个框选范围，结果持久化到 ini `[Measure]` 段（客户区坐标）：

1. **测量坐标**：与坐标模块同流程——点该行「测量」→ 切到游戏将鼠标指向目标后按 `F5` 记录；再点一次按钮取消
2. **框选范围**：点该行「框选」开启 → 切到游戏**按住鼠标左键拖出矩形后松开**，按下/抬起两点规范化为范围 (x1, y1, x2, y2)；框选中按 `F5` 重新开始，再点一次按钮取消；范围小于 4×4 像素视为误触作废
3. 注意：`F5` 只在「开发」子页生效（与旋风/坐标子页共用标定键，按当前子页路由）；框选钩子仅旁观记录，左键拖拽会照常作用于游戏，请避开游戏内操作；`F12` 急停会取消进行中的框选

### 研发设置与日志面板

「研发」模块配置区提供调试模式开关与日志输出级别（DEBUG / INFO / WARN / ERROR，存 ini `[Dev]` 段），驱动底部全局日志面板的显示过滤；日志面板按级别着色（DEBUG 灰 / INFO 白 / WARN 橙 / ERROR 红），标题行右侧按钮可折叠/展开。

### 交易模块（市场比例抓取）

「交易」模块页内嵌四个子标签：

1. **默认通货**：一键抓取三种默认通货（崇高石/混沌石/神圣石）两两之间的市场比例（3 对 × 双向，每方向取第 1 条挂单），同步到 Web「交易 → 默认」页参与最佳兑换计算（买边按 Currency Exchange 值折算金币消耗）；结果不在本页展示，同类别同方向自动记录每次只保留最近一次。启动热键默认 `F9`（存 `[MarketScan] HotkeyDefault`）
2. **指定**：输入指定通货的游戏内英文全名（如 Orb of Annulment，存 `[MarketScan] CustomCurrency`），抓取它与三种默认通货的市场比例（3 对 × 双向），同步到 Web「交易 → 指定」页参与最佳兑换计算；每次只保留最近一次。启动热键默认 `F10`（存 `[MarketScan] HotkeyCustom`）
3. **自动**：预留（定时自动抓取），暂未开放；输出对应 Web「交易 → 自动」页
4. **比例测试**：A/B 双向抓取测试入口——填通货 A/B 英文全名与启动热键（默认 Divine Orb / Chaos Orb / `F8`）→ 点「保存配置」生效 → 游戏内打开交易市场按热键（或点「测试抓取」）→ 完成后弹出提示框，结果区并排展示 B→A 与 A→B 挂单表（序号/比例/库存，每方向最多前 3 条，无交易显示「无可用交易」），供标定核对与调试

抓取期间请勿操作键鼠；坐标未标定、窗口未找到、OCR 失败等异常在状态栏显示中文原因；单对抓取失败不中断其余对（详见日志面板）。抓取前需先在「研发 → 开发」页标定 point1~5 与 range3。

### 通货市场比例抓取（抓取逻辑）

`poe2_tools/modules/market/` 提供游戏内置交易市场的双向兑换比例抓取：选定通货 A/B 后，自动在「我需要的/我拥有的」两侧搜索选择通货、点市场比率按键、对结果面板截屏并 OCR 解析每行挂单的比例与库存（库存识别不到显示 "-"），返回 `{"success", "pair", "b_to_a", "a_to_b"}` 数据契约（某方向解析不出比例时对应列表为空数组；单方向截屏/OCR 失败不影响另一方向）。

- **坐标**：复用开发页测量槽位——point1~5 = 我需要的/我拥有的/搜索框/市场比率按键/搜索结果首项，range3 = 结果面板（另加 `[MarketScan] RangeOffsetX/Y` 偏移修正，默认 -10/+20）；未标定抛 `UnsetCoordinateError`
- **解析**：OCR 输出带检测框坐标的文本块，按行聚类后行内配对比例与库存（库存列在左/右两种布局都兼容；库存支持千分位逗号/点与小数），比例缺失的行自动跳过；某方向首次解析为空时自动重试一次（再点市场比率键）
- **延时**：`[MarketScan]` 段 `ClickDelay`/`SearchLoadDelay`（粘贴后等下拉刷新）/`UiRefreshDelay`（市场面板刷新）/`SelectDelay`（选中搜索结果后生效）（默认 300/1200/800/500ms），带 ±30% 抖动
- **调试截图**：每次抓取把结果面板截图存到 `logs/market/b_to_a.png` / `a_to_b.png`（同名覆盖），OCR 识别行以 DEBUG 级写入日志面板（研发页开调试可见）
- **批量抓取与同步**（`exchange.py`）：`default_pairs()`/`custom_pairs(name)` 生成通货对（默认三通货两两 3 对 / 指定通货 × 三默认 3 对），`ExchangeScanRunner` 顺序执行 scan（单对失败记 errors 继续），把每方向第 1 条挂单的市场比率「x:y」（x 个「我需要的」= y 个「我拥有的」）换算为 side=buy 买边汇率，经 `publish_rates()` 写入 `web/data/economy.db`（`trade_rates.source='auto'`，并按 `category` 归入交易菜单对应页面：默认通货抓取 → default「交易·默认」页，指定抓取 → custom「交易·指定」页；同类别同方向旧自动记录整体替换，每次只保留最近一次）；最佳兑换路径与金币折算由交易页面 `/api/trade/state?category=...` 按最新汇率现算
- **安全**：Ctrl 修饰键（反转方向点击）try/finally 成对释放；OCR 用 rapidocr-onnxruntime（懒加载，可注入替身）
- **调用**：`CurrencyTradeScanner(load_settings()).scan("Divine Orb", "Chaos Orb")`，同步阻塞，界面层需在工作线程中执行

## 经济记录（Web 应用）

独立的 Web 应用，记录 poe2db.tw（简体中文站 /cn）14 个经济模块的价格快照，与桌面工具互不影响。

### 菜单体系标准

全应用统一三级菜单，**所有新增页面必须按此标准接入，不允许在内容区自设菜单列**：

1. 顶部为一级菜单（经济 / 交易 / 策略 / 做装 / 开荒）
2. 左侧边栏为二级菜单（`.side-l2`，纯分组标签，不可点击）
3. 三级菜单（`.side-item.sub`，即页面）缩进嵌套在所属二级菜单下方，点击切换内容区页面

当前实例：做装 → 戒指（稀有度）；交易 → 市场比例（默认、指定、自动）；经济 → 工具（信息库）。例外：经济页的 14 个经济模块不是菜单页面，而是同一页面内的数据视图，在内容区页内模块列切换（2026-10-03 确认，不拆分为侧边栏页面）。经济页侧边栏顶部另有「赛季」数据切换区，不属于菜单层级。

### 启动

`uv run python -m web.app`，浏览器打开 http://127.0.0.1:8321 。

### 使用方式

1. 首次使用在「赛季管理」面板录入赛季名称与开服日期（如 0.5.5闪回 / 2026-09-04）；左侧赛季列表默认选中当前赛季（开服日期最新者），新旧赛季数据都保留可查
2. 页内左侧模块列选择经济模块（通货/碎片/驱灵仪式等 14 个），点「刷新本模块」抓取该模块当前价格；刷新中按钮转圈禁用
3. 表格复刻原站：图标 + 简体名 + 英文小字 + Wiki 链接、24h Value（含 ≈N 混沌换算）、7 天迷你走势 + 红/绿涨跌幅、24h 交易量
4. 表头点击可按价格/涨跌幅/交易量排序（升降切换）；搜索框同时匹配中文与英文名
5. 「开服天数」下拉筛选历史快照（开服天数 = 快照日期 - 开服日期 + 1），默认最新
6. 「定时抓取配置」面板：开关、开服 ≤ N 天（默认 14）每天定时抓、之后每周定时抓；保存后立即生效
7. 价格基准为神圣石；抓取「通货」模块时自动更新混沌⇄神圣汇率，其他模块价格据此换算出 price_chaos

### 交易（顶部一级菜单 → 市场比例 → 默认 / 指定 / 自动）

交易菜单下的三个三级页面，数据全部由游玩工具「交易」模块对应子标签抓取同步（桌面端直接写库，页面只读展示，**无手动录入入口**），按最新比例自动计算最优兑换路径与套利机会，目标是根据差价快速积攒通货。所有同步记录永久保存（`trade_rates` 表，`category` 列区分归属页面），为后续智能优化积累数据。

1. **默认**：崇高/混沌/神圣三通货两两市场比例（游玩工具「默认通货」子标签抓取，热键 F9）；**指定**：指定通货与三通货的市场比例（「指定」子标签，热键 F10）；**自动**：定时抓取输出（游玩工具「自动」子标签，暂未开放）
2. **Currency Exchange 值（金币/个）**：崇高/混沌/神圣各一个费率，优先取信息库 wiki 抓取值，可手动覆盖（清空恢复信息库值）；三个页面共用
3. **金币 ⇄ 通货转化比例**：由费率直接推导（1 通货 = VE 金币，1 金币 = 1/VE 通货），并按最优路径折成混沌展示
4. **市场比例表**：本页面类别当前生效的汇率（买/卖类型、方向、市场比例、折合 1 单位、同步时间），同方向只保留最近一次
5. **最佳兑换方案**：以每个方向+买卖侧的最新比例构建汇率图，简单路径 DFS 求兑换率最高的路径；买边按有效汇率（扣除金币费折算）计算，路径中买边标 [买]
6. **套利机会**：自动枚举乘积 > 1 的兑换环，按收益率降序展示；计入金币费后的伪套利（看似赚钱实则被金币费吃掉）不会被报出
7. **同步历史**：本类别最近 30 条记录（含买/卖类型），误同步可删除
8. 计算逻辑在 `web/trading.py`（纯函数），单测覆盖最优路径、套利环与金币费折算

### 信息库（经济 → 工具 → 信息库）

物品基础信息库，数据来自已抓取的经济模块物品 + 各物品 wiki 页（poe2db.tw），为后续交易分析提供金币消耗数据。

1. 表格列：图标 + 中/英文名、所属模块（中文名 + 英文 slug）、**Currency Exchange**（游戏内市场交易时每单位物品消耗的金币，如神聖石 800 金币）、Wiki 外链、信息抓取时间
2. 「抓取 Wiki 信息」：后台线程逐个请求有 wiki 链接且尚未抓过的物品页（限速 ≥ 1 秒/次），从属性表 `Currency Exchange` 行提取金币值入库（`item_info` 表）；进度实时展示，单个物品失败不中断
3. 「全部重抓」：忽略已有数据全部重新抓取（版本更新金币值变化时用，耗时较长）
4. 搜索框对物品中/英文名、模块中/英文名（slug）、wiki_slug 做服务端模糊检索（防抖 300ms）；模块下拉可过滤单个模块；金币列表头点击可排序
5. wiki 页同时提取 BaseType 中/英文名称存库（`item_info.name_zh/name_en`），展示时优先于经济页名称，保证中英文都可被检索

### 做装（顶部一级菜单）

做装流程记录页，用流程图展示做装操作模块。菜单遵循全应用三级标准：顶部一级菜单（做装）→ 左侧边栏二级菜单（装备部位：戒指）→ 二级菜单下嵌套的三级菜单（页面：稀有度）→ 内容区直接展示流程图，无内容区菜单列。

1. 点击顶部「做装」进入；左侧边栏「戒指」下点选三级页面（稀有度），内容区展示对应流程图；点击「经济」返回经济页
2. 「稀有度戒指」流程图（目标：52% 稀有度 + 双 T1 点伤 + 抗性戒指）：
   - 模块 1 底材：锁后缀 T1 稀有度金光戒指（82 底材，Alt 确认锁的是非工艺词条）→ 剥离石剥到一条词缀 + 锁词缀 → 混沌石开 C
   - 判定分支：C 出 T1 点伤 → 模块 2.1 双点伤 + 品质（完美崇高石 + 左旋 + 攻击催化剂喜悦 → 右旋 + 普通 E 打后缀 → 品质精华 + 右旋结晶吃后缀打品质 → 削切 + 混沌石洗出后缀 → 古老的骨头 + 左旋死灵占前缀）；C 出 T1 前缀稀有 → 分支 2.2 放弃双点伤（骨头解密成本太高）；C 出 T1 全抗 → 分支 2.3 看经济条件，不好按稀有度分支处理
   - 模块 3 洗后缀循环：缺抗性换对应抗性催化剂 / 不缺则右旋结晶 + 迅捷合金打攻击速度 → 完美 E → 不理想则右旋废止 + 剥离洗一条后缀 → 循环直到满意
3. 流程图为纯前端 HTML/CSS 组件（FlowNode/FlowArrow），无新增依赖；做装页侧边栏与经济页共用同一套二/三级菜单样式（`.side-l2` / `.side-item.sub`）
