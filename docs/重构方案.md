# 重构方案

> 项目文档：poe2_tools 全盘重构方案。本文档是重构各期的执行依据：每期开工前对照本方案，完成后更新进度。
> 起草：2026-10-14。背景：项目代码由 Kimi Code 生成，现由 Claude Code 接手，基于当前项目功能做重构分析与优化。

---

## 1. 背景与目标

### 1.1 背景

桌面端于 2026-10-01 从 AHK 迁回 Python 后，功能快速迭代（旋风引擎、瓦地图、市场抓取、输入记录等），代码由 Kimi Code 生成，能力上限导致积累了一批结构性问题。现由 Claude Code 接手，在**不改变产品功能定位**（半自动化辅助：人脑决策、脚本执行，拒绝全 Bot）的前提下做系统性重构。

### 1.2 目标（按优先级）

1. **可维护**：消灭上帝类/上帝函数，加功能不再牵动大半个仓库。
2. **去重复**：契约常量单一来源，UI 公共代码收敛，推翻「不抽公共包」旧决策。
3. **可排查**：日志单轨化，消灭静默 except，出问题能定位。
4. **稳定性**：排查并修复现有 bug/隐患，补纯逻辑测试防回归。
5. **配置统一**：cyclone config.json 合并进 poe2_tools.ini，单一配置入口。

### 1.3 已确认的需求决策（2026-10-14 与用户确认，详见 response.md）

| 决策项 | 结论 |
|--------|------|
| 范围 | 桌面端全部 + web/ 一并重构 |
| 行为容忍 | 允许重新设计；游戏内行为每期人工验证 |
| 复用策略 | 全面改为抽取公共模块（推翻 2026-09 旧决策，AGENTS.md 同步） |
| 配置体系 | cyclone config.json 合并进 ini，迁移期保留 config.json 读取兼容 |
| 日志形态 | core 提供统一 logger 工厂（命名 logger + 文件/控制台 handler），bus 仅作 UI 展示订阅；模块内禁止 print |
| 死代码 | bridge/server.py + Bridge 配置段直接删除；ahk/ 进入删除流程 |
| 测试 | 重构+补测试（纯逻辑，注入式替身） |
| 交付 | 分阶段，风险从低到高；每期独立 changelog/commit/人工验证，通过后进下一期 |

## 2. 现状调查摘要

代码总量约 15,600 行（不含 .venv/ahk/tests 约 8,600 行）。桌面端分层 config(831) / core(431) / modules(3,296) / bridge(189) / ui(2,983)，web 端 1,922 行。

### 2.1 符合预期的部分（重构中保持）

- 分层方向基本被遵守：modules 不 import ui，无反向依赖；`main.py` 是 3 行薄壳。
- `cyclone/` 的纯逻辑隔离是全仓最佳案例：`__init__.py` 只导出 fsm/vision 纯逻辑，engine/capture/executor 显式导入，dxcam 懒导入隔离在 capture.py。此模式向其他模块推广。
- core/ 职责清晰：input.py（键鼠模拟+按键台账）、window.py、hotkey.py、scheduler.py（纯逻辑）、clipboard.py。
- modules 间依赖方向合理（map_runner→bag、market 内部 exchange→scanner）。
- 测试基础设施好：conftest.py autouse fixture 把 ini 重定向到临时目录；map_vaal 的 `MapVaalDriver` 注入式替身是补测试的现成范式。

### 2.2 Top 问题清单（按严重度）

**P0-1 上帝类/上帝函数对**
- `ui/app.py`（828 行）：`Poe2ToolsApp` 一肩挑——构造全部 8 个业务模块、构建全部 UI、16 个热键注册、三套标定流程状态机（F5 单点/右键两角/左键框选）、旋风引擎待启动轮询、500ms 全局状态轮询、配置保存/急停/退出；直接 import 20+ 模块。
- `config/settings.py`：`load_settings`（363 起，180 行）、`save_settings`（545 起，110 行），`settings.py:382-541` 连续 160 行同构的 `_clamp(_to_int(_read_value(...)))` 模式。

**P0-2 契约常量三处手工同步**
- `ITEM_PREFIX = "item:"`：`modules/market/exchange.py:42` 与 `web/trading.py:27` 各定义一份。
- `CATEGORY_LABELS`（exchange.py:39）与 `web/db.py TRADE_CATEGORIES`。
- 候选价值区间 0.5~20：`settings.py:240-241`、`modules/market/arbitrage.py:26-27`、`web/trading.py:197-198`，共 3 处。

**P0-3 逐字重复 + ui 绕过 core**
- `ui/general_module.py:86-152` 与 `ui/tablet_module.py:99-165`：`_entry_row`、`_hotkey_row`、`_refresh_hotkey_displays`、`_start_capture`、`_capture_worker`、`_finish_capture`、`_read_hotkey` 约 70 行逐字重复；widgets.py 已有共享部件却未收进去。
- `general_module.py:20`、`tablet_module.py:20` 直接 `import keyboard` 做热键捕获，未走 `core/hotkey.py`。

**P1-4 日志四轨并行 + 静默失败**
- 4 套并存：`print()`（base.py:40、combat.py:45、scanner.py:97、recorder.py:62）、bus.log 回调、`logging.getLogger`（core/hotkey.py:18、cyclone/engine.py:54）、cyclone 自有 mlog 文件日志。web 端完全无 logging。
- 静默/裸 except：`ui/app.py:800`（保存配置失败静默 pass）、`bridge/bus.py:47`（订阅者异常吞掉）、`core/input.py:74`、`core/hotkey.py:69/77`、`modules/base.py:80-86`（ToggleRunner 工作线程 `_work` 抛异常无声消失，仅 finally 复位状态）。

**P1-5 死代码**
- `bridge/server.py` 的 `BridgeServer` 全仓无调用方（grep 仅 settings.py 读写 bridge_enabled/bridge_port，app.py 从不启动它）——死代码 + 死配置。
- `docs/architecture.md` 与 bus.py 注释引用的内容已不覆盖当前分层（过时文档）。

**P2-6 配置双轨**
- 桌面 ini（settings.py）+ 旋风 `modules/cyclone/config.json`（config.py 深合并默认值）；app.py 里两种写路径并存（`_record_pending_calibration` 写 ini vs `_finish_mark` 写 config.json）。

**P2-7 测试缺口**
- 无测试：`ui/` 全部（含 app.py）、`bridge/`、cyclone engine/executor/capture/loot、recorder 本体、market driver/ocr/parser、web/app.py API 层、web/service.py、web/scheduler.py、bag.py/waystone.py 本体。
- web 端几乎无类型标注（trading.py、app.py）。

**P3-8 其他**
- web/app.py 路由+业务混合（`_unit_labels`/`_gold_values` 等计算函数塞进 app.py:198-270）；web/db.py 622 行集中全部 SQL。
- 硬编码集中：窗口尺寸 1180x720（app.py:142）、配色散落、map_vaal.py:51-75 亮度阈值、cyclone/config.py 2560×1440 ROI 默认值。属「有意硬编码」但应集中管理。

## 3. Bug/风险清单（第 0 期排查确认项）

以下为调查阶段已发现、待第 0 期逐条复现确认的隐患：

| # | 位置 | 描述 | 风险 |
|---|------|------|------|
| R1 | modules/base.py:80-86 | ToggleRunner 工作线程 `_work` 抛异常后无声消失，仅 finally 复位状态，无日志无 UI 提示 | 功能静默失效，用户误以为在运行 |
| R2 | ui/app.py:800 | 保存配置失败 except 静默 pass | 配置丢失无感知 |
| R3 | bridge/bus.py:47 | 订阅者回调异常被吞 | 日志/事件链断裂难定位 |
| R4 | core/input.py:74、core/hotkey.py:69/77 | 裸 except | 掩盖真实错误 |
| R5 | web/service.py:65/89 | 刷新任务异常静默吞掉 | Web 抓取失败无日志 |
| R6 | 配置双轨写路径 | app.py 中标定结果可能写 ini 与 config.json 两处，存在不一致窗口 | 标定丢失/串值 |
| R7 | core 依赖 config | core/scheduler.py:17、core/window.py:18 import config.settings，config↔core 双向认知 | 分层边界模糊（core 应从参数接收配置） |

> 第 0 期排查结论（2026-10-14）：
> - **确认并修复**：R1（ToggleRunner 工作线程异常落 ERROR 日志）、R2（保存配置失败落 ERROR 日志）、R3（bus 订阅者异常记日志）、R7（scheduler 最小间隔改构造注入、窗口标题改启动注入，core→config 方向本就合法、无循环，属风格问题）。
> - **确认不修**：R4（input.py:74 / hotkey.py:69/77 为「释放/注销失败静默忽略」的有意设计，注释已说明，保持原行为）；R5（web 抓取失败已有 _REFRESH_STATUS["error"] 状态通道上报前端，缺日志属第 5 期统一 logging 范围）。
> - **确认存在、第 2 期修复**：R6（app.py 标定双写路径：货币/测量点写 ini，旋风 ROI 写 config.json，各自独立暂无冲突，随第 2 期配置合并消除）。

### 第 0 期 排查与清理（风险最低，先行）✅ 2026-10-14 完成

- 逐模块排查确认 §3 清单，产出最终 Bug 清单并修复（R1~R7，结论见上）。
- 删除 `bridge/server.py` 与 settings 的 Bridge 配置段（含读写与 [Bridge] 段写出）；bridge/ 只保留 bus。测试断言与 architecture.md、AGENTS.md 同步更新。
- docs/architecture.md 归并修正（移除 §3.2 WebSocket 桥与 §4 [Bridge] 表，更新 §1 分层图与 §2.4）。
- ahk/ 目录：已删除（用户确认，含 config/migrate.py 迁移逻辑与 tests/test_migrate.py）。
- **验收结果**：✅ uv run pytest 292 项全绿；git grep 无 BridgeServer 残留；桌面端 import 冒烟通过。
- **人工验证项**（待用户在游戏内执行）：桌面端正常启动、热键注册、F12 急停释放——见 docs/功能说明.md 待完成清单。

1. **安全约定不变**：F12 全局急停始终全局；任何按键操作必须在 finally 或急停函数中释放（core/input.py 按键台账模式保留并推广）。
2. **人工痕迹保留**：所有点击/按键保留随机延迟与抖动；禁止内存读取、注入、Hook 等侵入式技术。
3. **分层方向不变**：ui→modules→core→config，禁止反向依赖；core 只做硬件级能力，配置一律参数注入（修 R7）。cyclone 纯逻辑隔离模式推广到各模块。
4. **行为等价优先**：每期默认行为等价；重新设计项在该期计划中单独列出并说明影响面。
5. **复用新决策**：允许抽取公共模块，但公共代码必须有明确归属层与单一职责，不为复用而造抽象。
6. **小步快跑**：每期可独立验证、可独立回滚（独立 commit），游戏内人工验证通过才进下一期。

- **验收**：test_settings 扩展覆盖新读写机制与迁移兼容；现有 ini 文件加载结果逐字段等价（写对拍脚本核对）。

### 第 3 期 UI 层拆分

- `ui/app.py` 拆分：
  - 热键分派器（HotkeyDispatcher）：16 个热键注册/作用域/分派规则（功能热键 vs 页面动作键优先级、旋风页分派、F12 全局）集中一处，规则写成纯逻辑可测。
  - 标定控制器（CalibrationController）：三套标定状态机（F5 单点/右键两角/左键框选）拆出。
  - 模块注册表：8 个模块构造与导航组装拆出，app.py 只留窗口生命周期。
- 热键捕获公共代码收进 ui/widgets.py（`HotkeyCapture` 部件），general_module/tablet_module 复用。
- `import keyboard` 收进 core/hotkey.py，ui 不直接接触 keyboard。
- **验收**：热键分派规则纯逻辑测试（照 FSM 测试范式）；app.py 行数降至 ~300 以内；widgets.py 热键捕获部件单测。
